# 写实人物与真实 3D 校园楼宇制作流程

本文用于把 `Campus Horror Starter` 从灰盒原型升级为可用于正式开发的写实校园恐怖游戏。

目标不是单纯堆高面数，而是同时满足：

- 近距离看起来可信；
- 人物能正常绑定、动画和换装；
- 楼宇尺寸、材质和光照符合现实；
- Godot 运行稳定，普通游戏电脑也能达到可玩帧率；
- 每项素材来源和授权都可以追踪；
- 原始工程、游戏资产和最终场景彼此分离。

---

## 一、推荐软件组合

### 必备

- **Godot 4.3 或更新稳定版**：游戏逻辑、场景、灯光、碰撞、导航、动画状态机。
- **Blender 4.2 LTS 或更新稳定版**：人物修整、骨骼、动画处理、楼宇建模、UV、LOD、导出。
- **Git + Git LFS**：管理 `.blend`、`.fbx`、`.glb`、HDR、无损音频等大型二进制文件。

### 人物制作可选工具

- **MakeHuman / MPFB**：最快生成可商用的基础人体，核心人物资产为 CC0。
- **Blender Rigify**：自己制作骨骼和控制器时使用。
- **Mixamo**：快速自动绑定二足人物并取得走路、奔跑、跌倒、挣扎等动作。
- **Krita / GIMP / Substance 3D Painter**：皮肤、衣物、污渍和磨损贴图。

### 建筑与环境可选资源

- **Poly Haven**：CC0 HDRI、PBR 贴图和部分写实模型。
- **ambientCG**：CC0 PBR 材质、HDRI 和模型。
- **自己拍摄的照片**：用于学校墙面、地砖、门牌和旧物参考；不要直接把含人脸、车牌、校徽、商标的照片作为游戏贴图。

## 二、项目资产目录

正式素材按以下结构放置：

```text
assets/
├── characters/
│   ├── source/             # .blend、原始扫描、雕刻工程，不直接进游戏
│   ├── exports/            # 导出的 .glb
│   ├── textures/           # 皮肤、衣物、头发贴图
│   └── animations/         # 动画 .glb/.fbx/.bvh
├── environment/
│   ├── school/
│   │   ├── source/         # 楼宇 Blender 工程
│   │   ├── modules/        # 墙、门、窗、楼梯、栏杆等模块
│   │   ├── props/          # 桌椅、柜子、灯具、灭火器等
│   │   ├── textures/       # 建筑 PBR 贴图
│   │   └── exports/        # Godot 使用的 .glb
│   └── shared/
├── audio/
├── reference/              # 平面图、尺寸记录、气氛参考，不随游戏发布
└── licenses/               # 素材授权和来源记录
```

原则：

1. `source/` 保存可编辑源文件。
2. `exports/` 只放 Godot 实际导入的游戏资产。
3. 不要直接修改从 `exports/` 导入后自动生成的 Godot 缓存。
4. 所有第三方素材必须先登记到 `assets/ASSET_REGISTER.md`。

# 第一部分：真实人体模型

## 三、人物制作的三条路线

### 路线 A：最快可用——MakeHuman / MPFB

适合：普通学生、老师、保安、路人、远景人物。

流程：

1. 在 MakeHuman 或 Blender 的 MPFB 中生成基础人体。
2. 调整身高、体型、年龄感和脸部比例。
3. 添加基础服装和头发。
4. 导入 Blender。
5. 清理材质、骨骼和不需要的隐藏身体面。
6. 制作低模游戏版本和 LOD。
7. 绑定动画。
8. 导出 `.glb` 到 Godot。

优点：速度快、基础人体比例稳定、核心资产授权宽松。

缺点：默认人物容易有“人偶感”，必须继续处理皮肤、头发、眼睛、衣物褶皱和面部细节。

### 路线 B：质量与成本平衡——现成人体 + Blender 深度修改

适合：主角、关键 NPC、女鬼。

流程：

1. 取得明确允许游戏使用和修改的人体基础模型。
2. 在 Blender 中重新调整面部和身体比例。
3. 重做或改造头发、服装、皮肤材质。
4. 删除不可见身体区域，避免衣服下面仍渲染完整人体。
5. 重新拓扑或减面。
6. 绑定标准人形骨架。
7. 制作表情 Blend Shapes。
8. 制作专属动作和受惊、抽搐、爬行等恐怖动作。

### 路线 C：最高质量——雕刻/扫描 + 重拓扑

适合：最终商业版主角和女鬼特写。

流程：

1. Blender Sculpt 或合法人体扫描。
2. 高模雕刻皮肤、皱纹、伤口和衣物细节。
3. 重拓扑为动画友好的四边面低模。
4. UV 展开。
5. 将高模细节烘焙到低模 Normal、AO、Curvature。
6. 制作 PBR 材质。
7. 骨骼、权重、表情、动画。
8. 导出并在 Godot 中完成材质和动画配置。

扫描真人前必须取得书面授权，明确允许：建模、修改、游戏发行、宣传使用和商业使用。不要未经允许扫描同学、老师或现实中的特定人物。

## 四、人物推荐技术指标

以下是本项目的建议目标，不是引擎硬限制。

### 主角/关键 NPC

- LOD0：约 60,000～120,000 三角面。
- LOD1：约为 LOD0 的 50%。
- LOD2：约为 LOD0 的 20%～25%。
- 材质槽：尽量控制在 3～6 个。
- 身体/衣物贴图：2K。
- 脸部特写：可使用 4K，但仅限少量关键人物。
- 骨骼：优先控制在 80～150 根以内。
- 表情：至少包含眨眼、张嘴、皱眉、恐惧、痛苦。

### 女鬼

女鬼不等于无限高面数。恐怖感主要来自：

- 不自然但有规律的动画；
- 头发与脸部轮廓；
- 眼神和嘴部表情；
- 声音与出现时机；
- 灯光下的局部可见性；
- 追逐速度变化和路径选择。

女鬼建议：

- 使用与普通人物兼容的基础骨架，额外增加头发、下颌、手指或脊柱控制骨。
- 为走、慢行、发现、冲刺、攻击、搜索、待机分别制作动画。
- 不要依赖透明材质制造整只鬼；透明会增加渲染压力。优先使用实体材质、边缘光、粒子和局部透明。

---

## 五、人物 Blender 清理清单

导入人体后逐项检查：

- 模型朝向：面向 Blender `-Y` 或按团队统一方向。
- 单位：1 Blender 单位 = 1 米。
- 人物身高是否合理。
- 应用 Rotation 和 Scale。
- 删除身体内部、衣物内部和重复网格。
- 修复反向法线和重叠顶点。
- 检查肩、肘、膝、手指拓扑是否适合弯曲。
- 将眼球、牙齿、舌头保留为独立对象或合理合并。
- 头发尽量使用发片或游戏可承受的几何体，避免数十万根曲线直接导入。
- 材质名称清晰，例如 `M_Student_Face`、`M_Uniform`。
- 骨骼名称保持稳定，不要每次导出都改变。

## 六、人物动画流程

### 使用 Mixamo

1. 从 Blender 导出仅包含人物网格的 FBX。
2. 上传到 Mixamo 自动绑定。
3. 下载 T-Pose 角色一次。
4. 分别下载所需动作。
5. 在 Blender 中统一骨架、帧率和动作名称。
6. 将多段动作整理到同一角色工程。
7. 输出 `.glb`。

建议动作：

- Idle / Breathing
- Walk / Fast Walk
- Run / Sprint
- Turn Left / Turn Right
- Search
- Alert
- Chase
- Attack
- Hit Reaction
- Fall / Get Up
- Crawl
- Door Interaction
- Pick Up

注意：Mixamo 可以用于游戏，但不要把下载的原始人物和动作文件作为独立素材包公开再分发。公开仓库中优先放经过项目处理的导出资产，并保留来源记录。

### 使用 Rigify

适合需要专属骨骼、复杂女鬼动作或长期维护的角色。

流程：

1. 在 Blender 启用 Rigify。
2. 添加 Human Meta-Rig。
3. 对齐人体关节。
4. Generate Rig。
5. 将网格绑定到生成骨架。
6. 修正权重。
7. 制作动作。
8. 导出时只选择最终变形骨架和网格，不导出控制器小部件。

---

## 七、人物导出到 Godot

推荐格式：**glTF 2.0 二进制 `.glb`**。

Blender 导出建议：

- Selected Objects：开启。
- Apply Modifiers：开启。
- UVs、Normals、Tangents：开启。
- Materials：Export。
- Animation：开启。
- Skinning：开启。
- Shape Keys：需要表情时开启。
- 不导出 Blender 灯光和相机，游戏灯光在 Godot 中重新制作。
- 避免负缩放；镜像对象导出前应用变换。

Godot 中：

1. 把 `.glb` 放到 `assets/characters/exports/`。
2. 等待自动导入。
3. 打开 Advanced Import Settings。
4. 检查 Skeleton3D、AnimationPlayer 和材质。
5. 为角色创建 Inherited Scene，不直接修改导入场景。
6. 在继承场景中添加碰撞、AI、交互点和音频节点。

# 第二部分：真实 3D 校园楼宇

## 八、不要一次建完整学校

最容易失败的方式是：在一个 Blender 文件里建整所学校，再作为一个巨大 Mesh 导入。

正确方法是模块化：

```text
基础结构
├── Wall_1m
├── Wall_2m
├── Wall_4m
├── Wall_Door
├── Wall_Window
├── Floor_2m
├── Ceiling_2m
├── Door_Single
├── Window_Standard
├── Stair_Straight
├── Stair_Landing
├── Railing
└── Column
```

然后按楼层、区域和房间拼装：

```text
School/
├── Floor_01/
│   ├── Corridor_A
│   ├── Classroom_101
│   ├── Classroom_102
│   └── Stairwell_East
├── Floor_02/
└── Basement/
```

这样才能实现：

- 分区加载；
- 遮挡剔除；
- 单独修改房间；
- 重复使用模块；
- 控制碰撞和导航；
- 不同楼层独立布光。

---

## 九、楼宇制作流程

### 阶段 1：现实测量与参考

准备：

- 平面图或手绘尺寸图；
- 楼层高度；
- 走廊宽度；
- 门窗尺寸；
- 楼梯级数、踏步高度和宽度；
- 墙面、地面、天花板材质照片；
- 灯具和家具分布。

没有真实测量时可先使用以下原型值：

- 单层层高：3.2～3.8 米。
- 普通门洞：约 0.9 × 2.1 米。
- 双开门：约 1.5～1.8 米宽。
- 普通走廊：约 2.0～3.0 米宽。
- 楼梯踏步：约 0.15～0.17 米高，0.28～0.30 米深。
- 墙体厚度：0.12～0.24 米。

这些只是灰盒起点，应以实际建筑或设计目标为准。

### 阶段 2：Godot 灰盒

先用简单盒子完成：

- 玩家完整路线；
- 房间和走廊比例；
- 追逐距离；
- 门和楼梯；
- 谜题位置；
- 女鬼出生点；
- 躲藏点；
- 安全区和检查点。

必须先确认游戏好玩，再做写实模型。

### 阶段 3：Blender 模块化建模

- 使用 0.1 米或 0.25 米网格吸附。
- 所有建筑模块原点位置统一。
- 门轴放在真实铰链位置。
- 窗户、抽屉、柜门等可动画物体必须独立。
- 墙、地面和天花板不要全部合并成一个物体。
- 重复家具采用同一模型实例。
- 碰撞网格单独建低模，不直接使用高细节模型碰撞。

### 阶段 4：写实材质

每套 PBR 材质至少准备：

- Base Color / Albedo
- Normal
- Roughness
- Metallic（仅金属需要）
- Ambient Occlusion
- Height / Displacement（按需要）

校园恐怖场景重点材质：

- 旧水泥墙；
- 发黄乳胶漆；
- 磨损地砖；
- 水磨石；
- 生锈金属；
- 潮湿墙面；
- 木门和旧漆；
- 灰尘玻璃；
- 荧光灯塑料罩；
- 黑板、课桌和储物柜。

真实感来自粗糙度变化、污渍位置和边缘磨损，不是单纯把贴图分辨率开到 8K。

### 阶段 5：道具层

楼宇主体完成后加入：

- 课桌椅；
- 储物柜；
- 消防栓和灭火器；
- 电箱；
- 风扇；
- 饮水机；
- 公告栏；
- 门牌；
- 垃圾桶；
- 扫把和拖把；
- 监控摄像头；
- 电线槽；
- 插座和开关；
- 纸张、书本和个人物品。

道具应服务于剧情和空间识别，不要无目的堆满场景。

## 十、楼宇导出规则

建议每个可独立管理的区域单独导出：

```text
school_floor01_structure.glb
school_floor01_props.glb
school_floor01_doors.glb
school_floor02_structure.glb
basement_structure.glb
shared_furniture.glb
```

命名约定：

- `SM_`：静态模型。
- `SK_`：骨骼模型。
- `M_`：材质。
- `T_`：贴图。
- `AN_`：动画。
- `COL_`：碰撞网格。
- `OCC_`：遮挡体。

示例：

```text
SM_School_Wall_2m_A.glb
SM_Classroom_Desk_A.glb
SK_Ghost_Female_A.glb
AN_Ghost_Chase_A.glb
T_WallPaint_Dirty_BaseColor.png
T_WallPaint_Dirty_Normal.png
```

## 十一、碰撞与导航

### 建筑碰撞

- 墙、地板、楼梯使用简单 Box 或低模 Convex/Concave 碰撞。
- 门使用独立碰撞体并跟随门动画。
- 小道具若不可交互，不必都有碰撞。
- 不要用完整高模生成精细碰撞，会增加 CPU 和物理成本。

### 女鬼导航

- 每个楼层建立 NavigationRegion3D。
- 门口和楼梯保持导航网格连续。
- 动态门使用 NavigationObstacle3D 或重新设计导航连接。
- 女鬼的碰撞半径应略小于走廊和门洞的可通过宽度。
- 先在灰盒地图完成追逐 AI，再替换写实楼宇。

---

## 十二、灯光流程

不要依赖 Blender 场景灯光直接导入。

在 Godot 中重新建立：

- 月光或室外方向光；
- 走廊灯；
- 教室灯；
- 应急灯；
- 手电筒；
- 女鬼出现时的局部灯光变化；
- WorldEnvironment 的雾、曝光、色调映射和环境亮度。

恐怖场景不是越黑越好。玩家必须能辨认：

- 下一步去哪里；
- 哪些物品可交互；
- 女鬼大致位置；
- 安全区和危险区的视觉差异。

建议用灯光引导玩家，而不是一直用箭头和任务标记。

---

## 十三、性能优化目标

### 场景拆分

- 每层或每个区域独立场景。
- 远离玩家的楼层可以禁用或卸载。
- 重复模型使用实例，不复制网格资源。
- 大量相同小物体使用 MultiMeshInstance3D。

### LOD

- 人物至少 3 级 LOD。
- 大型家具和室外建筑准备 LOD。
- 小型室内道具可以通过 Visibility Range 直接隐藏。

### 遮挡剔除

校园室内很适合遮挡剔除：墙、楼板和封闭房间能阻挡大量不可见物体。

- 为整层或建筑区域设置 OccluderInstance3D。
- 门窗位置不要被错误的遮挡体封死。
- 使用 Godot 调试视图检查遮挡结果。

### 材质与贴图

- 同类墙体共用材质。
- 使用 Trim Sheet 和材质图集减少材质切换。
- 常规环境贴图以 1K～2K 为主。
- 只对镜头非常接近的关键物体使用 4K。
- 压缩贴图并检查显存占用。

### 推荐首个性能目标

- Windows 1080p。
- 中档独立显卡稳定 60 FPS。
- 集成显卡提供低画质模式，目标 30 FPS。
- 同屏可见三角面、灯光和阴影数量以实际 Profiler 为准，不以模型总面数判断。

## 十四、资产验收标准

### 人物

- [ ] T-Pose/A-Pose 正常。
- [ ] 走路时无滑步。
- [ ] 肩、肘、膝无严重塌陷。
- [ ] 眼球、牙齿、头发没有穿模。
- [ ] 动画名称清晰。
- [ ] LOD 切换不明显跳变。
- [ ] 材质在 Godot 中正确显示。
- [ ] 近距离没有明显法线和 UV 错误。

### 楼宇

- [ ] 尺寸与灰盒一致。
- [ ] 门、楼梯和走廊能够通行。
- [ ] 没有漏光、反向法线和可见缝隙。
- [ ] 碰撞简单且准确。
- [ ] 导航网格连续。
- [ ] 房间能独立隐藏或加载。
- [ ] 材质比例正确，不出现巨大砖块或微小地砖。
- [ ] 开门、抽屉、柜子原点正确。
- [ ] 遮挡剔除不会把可见物体错误隐藏。

## 十五、授权和隐私规则

每个第三方素材都必须记录：

- 素材名称；
- 作者或平台；
- 原始来源页面；
- 下载日期；
- 许可证；
- 是否允许修改；
- 是否允许商业使用；
- 是否允许重新分发原始文件；
- 本项目做过哪些修改。

优先级：

1. 自制素材；
2. CC0；
3. 明确允许游戏商用且可修改的许可证；
4. 其他授权必须单独审核。

禁止：

- 从其他游戏提取人物、建筑、动画、音效或贴图；
- 使用无法确认作者和许可证的网盘素材；
- 未经授权使用现实学校的校徽、品牌、人物肖像；
- 把“免费可下载”等同于“允许商用和重新分发”。

## 十六、建议的第一批正式资产

不要一开始制作整所学校。第一阶段只完成一段 10～15 分钟试玩：

### 人物

- 女鬼 1 名；
- 主角第一人称手臂 1 套；
- 剧情 NPC 1 名；
- 人物动作 12～20 个。

### 楼宇

- 一层走廊；
- 两间教室；
- 一间厕所；
- 一段楼梯；
- 一间地下室；
- 10～15 个可重复使用建筑模块；
- 15～30 个环境道具；
- 8～12 套可平铺 PBR 材质。

完成这一小段并达到稳定帧率后，再扩展其他楼层。

## 十七、最短落地顺序

1. 安装 Blender 和 Godot。
2. 用灰盒场景确定一段追逐路线。
3. 用 MakeHuman/MPFB 制作一个测试人物。
4. 用 Mixamo 或 Rigify完成基础动画。
5. 导出 `.glb`，替换当前胶囊女鬼。
6. 在 Blender 制作墙、门、窗、楼梯模块。
7. 用 PBR 材质替换灰盒表面。
8. 分区域导出 `.glb`。
9. 在 Godot 中重做碰撞、导航和灯光。
10. 开启 LOD、可见范围和遮挡剔除。
11. 用 Profiler 检查 CPU、GPU、显存和物理开销。
12. 登记全部素材许可证后再发布 Demo。
